These commands apply to `packages/b4`, the bulletin board in the main Cargo
workspace. The separate `packages/wbraid/crates/b4` implementation has its own
workspace and testing guide.

From `packages/`, using the repository's pinned Rust toolchain:

```sh
cargo test --locked -p b4 --features native --tests
cargo test --locked -p b4 --features native,client --tests
```

Install PostgreSQL and `libpq-dev`, or set `PG_BIN` to the directory containing
`initdb`, `pg_ctl` and `pg_config`. Run as an ordinary user. Each database test
owns a temporary cluster, listens only on a private Unix socket, and removes its
cluster on success or panic. No database URL, production credentials or cloud
account is needed. S3 URL tests use explicit synthetic credentials and perform
local presigning without contacting S3.

The suites check fixed wire vectors, malformed hash-list lengths, writer failures,
configuration membership and thresholds, signature rejection, configuration
artifact consistency, PostgreSQL field mapping and transaction rollback, and
HTTP handler status/inline-storage boundaries. The client fixture verifies that
creation time and signed statement time survive independently.

From the repository root, measure the native HTTP profile with the pinned
`cargo-llvm-cov` version:

```sh
python3 scripts/coverage/run.py b4 --baseline
```

CI compares lines, functions and LLVM regions separately with the PR's actual
base. Regions are not branch coverage. Inline tests and generated serialization
remain measured. The `client` feature is tested separately and is not included
in the native HTTP profile counters. The legacy `cfg(feature = "sqlcopy")` client
branch has no declared Cargo feature in this package, so it is not part of a
supported build or these measurements. If SQL-copy support is restored, run the
owned client timestamp/rollback contracts with that feature before enabling it.

The `monitor` feature currently imports undeclared `sqlx` and queries the former
SQLite schema. Its failing build is separate from the PostgreSQL server profile;
restoring the monitor requires deciding which database it should display. WASM,
cloud upload confirmation, multi-board transport failures and complete protocol
workflows require their own measurements. A passing native run does not cover
those paths.

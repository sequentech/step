# Run a Prepared Client Package

Use this procedure when the election authority supplies a prepared package whose README specifies
`./run-audit.sh OUTPUT_DIRECTORY`. The package includes the image, backups, integrity manifests
and an election-specific launcher. The launcher already sets the tally ID, public-key digest,
electoral-log system public key and environment slug. You supply only a new output directory.

This launcher is supplied with the prepared package. Building `packages/ballot-audit/Dockerfile.prod`
does not create it. The raw image and `audit-tally` still require their named options. If you have
only an image and separate backups, start with [Set Up the Audit Workstation](01-workstation.md).

## Before you start

- Read the package README and [Before You Start](../01-before-you-start.md).
- Use Linux amd64 with Bash, Docker, GNU coreutils, tar and gzip. Encrypted packages also need OpenSSL with PBKDF2 support.
- Allow four CPUs, 8 GiB of container memory, and working space for the image, backups and restored copies.
  Follow the package README for disk requirements.
- Obtain the expected archive digests through an authenticated channel separate from the archive.
- Confirm the packaged public values and backup digests with the election authority through an independently authenticated channel.
  `candidate-anchors-NOT-INDEPENDENT.json` records candidate values from captured evidence; it is not an authority attestation.
- Review the package provenance, capture times and eligibility snapshot. Separate database captures are not necessarily one consistent snapshot.

Keep the package, password and generated output private. Stop if any command or checksum check fails.

## 1. Check and extract the package

1. Make a fresh private working directory:

   ```bash
   umask 077
   WORK=$(mktemp -d "$HOME/election-audit-XXXXXX")
   cd "$WORK"
   ```

2. Copy the supplied archive and checksum files into this directory.
3. Set its plaintext archive name and extraction root from the package instructions:

   ```bash
   PACKAGE='election-verification.tar.gz'
   PACKAGE_ROOT='election-verification'
   ```

   Replace these example names with the supplied names.

4. For an encrypted package, check its digest before decryption:

   ```bash
   sha256sum -c "$PACKAGE.enc.sha256"
   ```

5. Decrypt with the settings supplied for that package. For AES-256-CBC with salted PBKDF2,
   600000 iterations and SHA-256, use:

   ```bash
   test ! -e "$PACKAGE" &&
   openssl enc -d -aes-256-cbc -salt -pbkdf2 -iter 600000 -md sha256 \
     -in "$PACKAGE.enc" -out "$PACKAGE"
   ```

   Enter the password at the hidden prompt. Do not put it in the command or audit notes.
   Skip steps 4 and 5 for an unencrypted archive.

6. Check the plaintext archive digest:

   ```bash
   sha256sum -c "$PACKAGE.sha256"
   ```

   CBC encryption does not authenticate the archive. Compare against the independently obtained digest before extraction.

7. Extract the archive:

   ```bash
   tar -xzf "$PACKAGE"
   cd "$PACKAGE_ROOT"
   ```

8. Check the package manifests:

   ```bash
   sha256sum -c SHA256SUMS
   sha512sum -c SHA512SUMS
   ```

**Expected result:** each checksum check shows `OK`. The extracted directory contains the
executable `run-audit.sh`, image, backups and provenance. Results are generated by your run.

## 2. Run the audit

1. Choose a new output path outside the extracted package:

   ```bash
   OUTPUT="$WORK/output"
   ```

   Do not create this directory. Its parent must exist; the output path itself must not exist.

2. Run the launcher and record its exit status immediately:

   ```bash
   ./run-audit.sh "$OUTPUT"
   audit_status=$?
   printf 'Verifier command exit code: %s\n' "$audit_status"
   ```

The launcher checks package integrity, loads the included image and checks its identity.
It mounts the backups read-only and starts the container with networking disabled.
It displays the native output and returns the Docker/verifier exit status.
No separate `docker load`, public-key arguments or production credentials are needed.

**Expected result:** the command shows backup checks, restore progress, audit steps and a
`Results` section. A successful run includes `Overall: Success` and
`ballot-audit: exit status 0`. Read the detailed output regardless of the final status.

## 3. Check and retain the output

1. Read `audit-output.log` in the output directory. Follow [Read the Results](../03-read-the-results.md).
2. Check the generated log digest:

   ```bash
   (cd "$OUTPUT" && sha512sum -c audit-output.log.sha512)
   ```

3. Record the command, exit status, image identity, input digests and output digest in the audit notes.

**Expected result:** the output directory contains `audit-output.log` and `audit-output.log.sha512`.
The checksum command shows `audit-output.log: OK`.

## If there is a problem

| Problem | Action |
| --- | --- |
| `run-audit.sh` is missing or documents different arguments. | Check the supplied README. This procedure applies only to the prepared one-argument launcher. |
| A checksum differs. | Stop and ask the election authority to resolve the difference. Do not edit a manifest to accept it. |
| `Output path already exists; choose a new directory.` | Choose a new path. Preserve previous output. |
| Docker cannot connect to its daemon. | Start Docker and check access before running the launcher again. |
| The command stops before producing `audit-output.log`. | Keep the terminal error and exit status. They are not a completed audit result. |

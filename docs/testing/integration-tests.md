# Integration Tests

## Tally Integration Test

The tally integration test is a comprehensive end-to-end test that validates the entire tally process from start to finish. It runs automatically on every pull request via GitHub Actions.

### What It Tests

- Complete tally ceremony workflow
- SQLite database generation
- Report generation (HTML, optionally PDF/XLSX)
- Result accuracy (vote counts, winner determination)
- Performance monitoring (execution time tracking)

### Running Locally

#### Prerequisites

1. **Docker and Docker Compose** - For running backend services
2. **Rust toolchain** (1.90.0) - For building step-cli
3. **Python 3** - For validation scripts
4. **PostgreSQL client** - For database operations
5. **SQLite3** - For result validation

#### Step-by-Step Instructions

1. **Start the development environment:**

   ```bash
   cd .devcontainer
   docker compose up -d postgres graphql-engine keycloak immudb windmill beat trustee1 trustee2
   ```

   Wait for services to be ready (~30 seconds):
   ```bash
   # Check that PostgreSQL is ready
   docker exec step-postgres-1 pg_isready -U postgres
   ```

2. **Build step-cli:**

   ```bash
   cd packages/step-cli
   cargo build --release --target x86_64-unknown-linux-musl
   ```

3. **Configure step-cli for local environment:**

   ```bash
   ./rust-local-target/x86_64-unknown-linux-musl/release/seq step config \
     --tenant-id "90505c8a-23a9-4cdf-a26b-4e19f6a097d5" \
     --endpoint-url "http://localhost:8080/v1/graphql" \
     --keycloak-url "http://localhost:8090" \
     --keycloak-user "admin" \
     --keycloak-password "admin" \
     --keycloak-client-id "admin-cli" \
     --keycloak-client-secret "admin-cli-secret"
   ```

4. **Import the test election fixture:**

   ```bash
   ./rust-local-target/x86_64-unknown-linux-musl/release/seq step import-election \
     --file-path ./test-fixtures/tally-integration-test/election-fixture.json \
     --is-local
   ```

   Note the election event ID from the output.

5. **Run the tally ceremony:**

   ```bash
   # Start tally
   ./rust-local-target/x86_64-unknown-linux-musl/release/seq step start-tally \
     --election-event-id <ELECTION_EVENT_ID> \
     --tally-type "ELECTORAL_RESULTS"

   # Note the tally ID from the output

   # Confirm trustee keys (if required)
   # ./rust-local-target/x86_64-unknown-linux-musl/release/seq step confirm-key-tally \
   #   --election-event-id <ELECTION_EVENT_ID> \
   #   --tally-id <TALLY_ID>

   # Complete the tally
   ./rust-local-target/x86_64-unknown-linux-musl/release/seq step update-tally \
     --election-event-id <ELECTION_EVENT_ID> \
     --tally-id <TALLY_ID> \
     --status "IN_PROGRESS"
   ```

6. **Wait for tally to complete** (check Windmill logs or database)

7. **Download results:**

   ```bash
   mkdir -p /tmp/tally-test-results
   ./rust-local-target/x86_64-unknown-linux-musl/release/seq step download-tally-results \
     --election-event-id <ELECTION_EVENT_ID> \
     --tally-id <TALLY_ID> \
     --output-dir /tmp/tally-test-results
   ```

8. **Validate results:**

   ```bash
   python3 ../../.github/scripts/validate-tally-results.py \
     --output-dir /tmp/tally-test-results \
     --expected-results-file ./test-fixtures/tally-integration-test/expected-results.json
   ```

9. **Cleanup:**

   ```bash
   cd .devcontainer
   docker compose down
   ```

### Troubleshooting

#### Services won't start

```bash
# Check Docker logs
cd .devcontainer
docker compose logs

# Restart specific service
docker compose restart postgres
```

#### PostgreSQL connection errors

```bash
# Verify PostgreSQL is running and accepting connections
docker exec step-postgres-1 pg_isready -U postgres

# Check PostgreSQL logs
docker compose logs postgres
```

#### Tally doesn't complete

```bash
# Check Windmill worker logs
docker compose logs windmill

# Check for tasks in Celery
docker compose exec windmill celery -A windmill inspect active
```

#### Import fails

```bash
# Verify the fixture file is valid JSON
jq . test-fixtures/tally-integration-test/election-fixture.json

# Check step-cli configuration
./rust-local-target/x86_64-unknown-linux-musl/release/seq step --help
```

### Creating Test Fixtures

See [Test Fixtures README](../../packages/step-cli/test-fixtures/tally-integration-test/README.md) for instructions on creating new test fixtures.

The current fixture needs to be generated by:
1. Creating a complete election event
2. Casting test votes
3. Completing key ceremony
4. Exporting with `--bulletin-board` and `--tally` flags
5. Anonymizing sensitive data

### Performance Monitoring

The CI workflow tracks execution time and alerts on performance regressions >10%.

To view performance history:
- Check the GitHub Actions run summaries
- Download the `performance-baseline` artifact from the main branch
- View `.github/performance-baseline.json` for historical data

### CI Workflow

The GitHub Actions workflow runs:
- On every pull request
- On pushes to main
- Nightly at 2 AM UTC
- Manual trigger via workflow_dispatch

Workflow file: `.github/workflows/tally-integration-test.yml`

### Adding More Test Cases

To add additional test scenarios:

1. Create a new fixture directory under `packages/step-cli/test-fixtures/`
2. Add expected results JSON
3. Update the workflow to run multiple test scenarios
4. Update validation script if needed for new checks

Reproducing the Air-Gapped ISO

The air-gapped installer is reproducible. Anyone who builds it from the same commits, on any x86_64 Linux machine, gets the same ISO and the same bundle, byte for byte. This page has everything needed to check that yourself: the inputs of the reference release, the exact build steps, and every hash to compare against.

The installer is built from the beyond repository, which pins this repository (step) as its step submodule. Its build is described in airgap/README.md in beyond, section "Reproducible builds"; this page is the procedure for an independent check of a release.

RELEASE_VERSION names the image tags and is written into the ISO, and SOURCE_DATE_EPOCH stands in for the clock everywhere a time would be recorded, so both must be exactly these values. Check out the commits, not the branch tips: the branches move on.

An earlier reference (ISO 90586ecb…, beyond 86cfdc61) was withdrawn and must not be used.

The match across Docker 29.8.1 and 29.0.4 and across Nix 2.34.8 and 2.28.4 is evidence for this release, not a guarantee for later ones. A bit-for-bit match is only guaranteed with the pinned toolchain below.

Requirements​

  • An x86_64 Linux host with Docker, git, curl, jq, sha256sum and GNU tar.
  • About 150 GB of free disk, 8 or more cores and 16 GB or more of RAM. The build takes between 50 minutes and 1.5 hours.
  • Internet access during the build: it fetches the sources, the pinned container images, the Nix packages from cache.nixos.org, and the Debian, PostgreSQL and other package mirrors the images install from. The machine that builds the ISO is not the air-gapped site.
  • Read access to the beyond repository, which is private. step is public. beyond's .gitmodules points at git@github.com:sequentech/step.git; without an SSH key for GitHub, the steps below switch the submodule to its HTTPS URL. That setting is local to the clone and does not change the build.

The build itself runs in two pinned images, each with empty storage, so the host's own Docker and Nix versions do not matter:

ToolImage
Docker Engine 29.8.1docker:29.8.1-dind@sha256:3f3c01aaaebf7cce837356b688b7c059a4749f10bd7660dec7c58fc454a283f0

airgap/prepare.sh starts its own BuildKit (moby/buildkit:v0.33.0, by digest) for every image build and removes it afterwards, and it brings its own Trivy, pinned by digest. The flake lock pins everything Nix builds. The Docker client and buildx plugin used inside the Nix container do not affect the output.

Build​

Run this on the host. It clones beyond at the release commit, starts the pinned Docker daemon, runs prepare.sh in the pinned Nix image, and copies the bundle to $HOME/airgap-check/out. It signs the bundle with a key generated for the check; the signature and the public key are left out of the comparison.

set -euo pipefail
W=$HOME/airgap-check; mkdir -p "$W/bin"
git clone https://github.com/sequentech/beyond.git "$W/beyond"
git -C "$W/beyond" checkout --detach 80dbb099f3b6668a5b1aa88978efa07da941a31c
git -C "$W/beyond" submodule init step
# Only needed without an SSH key for GitHub; local to this clone
git -C "$W/beyond" config submodule.step.url https://github.com/sequentech/step.git
git -C "$W/beyond" submodule update step                 # no --remote
git -C "$W/beyond" rev-parse HEAD HEAD:step; git -C "$W/beyond/step" rev-parse HEAD
git -C "$W/beyond" status --porcelain                    # must be empty

# Docker client and buildx for the Nix container (the client version does not affect the output)
curl -fsSL https://download.docker.com/linux/static/stable/x86_64/docker-29.8.0.tgz | tar -xz -C "$W/bin" --strip-components=1 docker/docker
curl -fsSL -o "$W/bin/docker-buildx" https://github.com/docker/buildx/releases/download/v0.31.1/buildx-v0.31.1.linux-amd64
chmod +x "$W/bin/docker" "$W/bin/docker-buildx"

cat > "$W/bin/inner.sh" <<'INNER'
set -euo pipefail
export NIX_CONFIG="experimental-features = nix-command flakes
substituters = https://cache.nixos.org/
max-jobs = 2
cores = 2"
for pkg in jq openssh gnutar coreutils findutils gnused gnugrep gawk gzip xz which curl; do
  for out in $(nix build --no-link --print-out-paths "github:NixOS/nixpkgs/cf5e76507c6e23b59f7e0ffcc7baa2a39ddd8442#$pkg^*"); do
    if [ -d "$out/bin" ]; then PATH="$out/bin:$PATH"; fi
  done
done
export PATH
mkdir -p /usr/libexec/docker/cli-plugins
ln -sf /opt/bin/docker-buildx /usr/libexec/docker/cli-plugins/docker-buildx
nix --version; /opt/bin/docker version; /opt/bin/docker buildx version
cp -a /src/beyond /work/beyond; chown -R root:root /work/beyond; cd /work/beyond
ssh-keygen -q -t ed25519 -N "" -C "reproducibility check" -f /work/signing_key
CONTAINER_ENGINE=/opt/bin/docker RELEASE_VERSION=ovcs-beyond-80dbb099-step-bc1158ec \
SOURCE_DATE_EPOCH=1792097421 SIGNING_KEY=/work/signing_key \
  ./airgap/prepare.sh 2>&1 | tee /work/build.log
INNER

docker network create airgap-check
for v in docker run nix work; do docker volume create "airgap-check-$v"; done
docker run -d --name airgap-check-dind --network airgap-check --privileged -e DOCKER_TLS_CERTDIR= \
  -v airgap-check-docker:/var/lib/docker -v airgap-check-run:/var/run \
  docker:29.8.1-dind@sha256:3f3c01aaaebf7cce837356b688b7c059a4749f10bd7660dec7c58fc454a283f0
until docker exec airgap-check-dind docker info >/dev/null 2>&1; do sleep 2; done
docker run --rm --network airgap-check \
  -v airgap-check-nix:/nix -v airgap-check-run:/var/run -v airgap-check-work:/work \
  -v "$W/beyond":/src/beyond:ro -v "$W/bin":/opt/bin:ro \
  nixos/nix:2.34.8@sha256:1a711b619c8a713eff32c3f8d8781b3b4d0130cb91c0a57f67e87abfeeb90b01 bash /opt/bin/inner.sh
mkdir -p "$W/out"
docker run --rm -v airgap-check-work:/work -v "$W/out":/out alpine \
  sh -c "cp -r /work/beyond/airgap-output /work/build.log /out/ && chown -R $(id -u):$(id -g) /out"

Lines with "Failed to send email via AWS SES" and "state=FAILED" in the log are expected output of unit tests. A non-zero exit of prepare.sh, or ERROR: failed to solve, is a failure: keep the end of $HOME/airgap-check/out/build.log.

    pm=$(jq -r '.manifests[] | select(.platform.os=="linux" and .platform.architecture=="amd64" and (.platform.variant // "")=="") | .digest' "$b")
  else pm=$dig; fi
  cfg=$(jq -r .config.digest "$X/blobs/sha256/${pm#sha256:}")
  echo "${name#docker.io/} $pm $cfg"
  jq -r '.rootfs.diff_ids | to_entries[] | "  \(.key) \(.value)"' "$X/blobs/sha256/${cfg#sha256:}"
done > "$W/digests.txt"; rm -rf "$X"
diff "$W/ref-digests.txt" "$W/digests.txt" && echo "ALL IMAGE DIGESTS AND LAYERS MATCH"

A reproduced build prints the reference ISO hash, then ALL 86 FILES MATCH, NIXOS SYSTEMS MATCH and ALL IMAGE DIGESTS AND LAYERS MATCH. Image config IDs in release/image-digests.txt are not OCI manifest digests, which is why the image archive is compared manifest by manifest and layer by layer.

To check the ISO you were given rather than only your rebuild, compare its SHA-256 with yours, and verify the delivered bundle with ./sequent verify --fingerprint and the fingerprint you received separately (airgap/README.md in beyond, section 5).

Known limits​

  • The Postgres image installs its extension packages from the live Debian and PostgreSQL mirrors. Two builds made together match, but a build made much later can differ in that image, and so in the image archive, its SBOM, the provenance report and the ISO. A difference confined to sequentech.local/postgresql points at this.
  • release/trivy-report.txt follows Trivy's live database and is not on the ISO. It is left out of the comparison.
  • The reference values are for the reference site, whose site.json and k3s-token are committed. A release for another site is reproduced from the same commits plus that site's two files, passed as SITE_FILE and TOKEN_FILE, and is compared against that release's own values.

If something differs​

Keep $HOME/airgap-check/out and the airgap-check-* Docker volumes, and send Sequent:

  1. The ISO's SHA-256.
  2. The output of the three comparisons, including the diffs.
  3. The host: operating system and kernel, CPU model and cores, and the docker version, nix --version and docker buildx version output at the start of build.log.
  4. The build duration and the end of build.log if it failed.
  5. For each differing image layer: its Dockerfile step (the image config's history entry at the same index), and the layer's file list with sizes, modes and times (tar -tv) and each file's SHA-256, so the differing file can be found by comparing two lists.

To clean up afterwards:

docker rm -f airgap-check-dind
docker volume rm airgap-check-docker airgap-check-run airgap-check-nix airgap-check-work
docker network rm airgap-check

How the build is kept reproducible​

Each of these was a real difference between two builders, found by comparing builds and fixed at the source. airgap/README.md in beyond keeps the full list of fixed settings.

CauseFix
Source file times and modes came from the checkoutImages and step-source.tar.gz are built from a copy of the tracked files, with SOURCE_DATE_EPOCH as every time and a fresh clone's modes
Sort order depended on the localeLC_ALL=C
The JDK download in harvest and windmill was not checkedChecked against its published SHA-256
fc-cache's log listed files in disk orderRemoved with the font cache
The Docker daemon's BuildKit reused earlier build contextsA BuildKit of its own per run, removed after it
The manifest format followed the BuildKit versionoci-mediatypes=true and BuildKit pinned
Keycloak's Dockerfile frontend was named by tagdocker/dockerfile:1.7 pinned by digest
docker save and Trivy's SBOMs picked up every tag the daemon held, including older releasesImages saved by name and tag; those tags dropped from the SBOMs
Docker 29.8 saves upstream images' attestation manifests and 29.0 does notOnly this platform's manifest, config and layers kept in the archive
The toolbox image archive took its builder's file ownerRepacked with fixed owners, modes and times

For later releases​

Each release that is meant to be checked independently publishes the same set of values as the reference above: the beyond and step commits, RELEASE_VERSION, SOURCE_DATE_EPOCH, the site file and token used, the ISO SHA-256, checksums.txt without the signing key and the Trivy report, the NixOS system paths and NAR hashes, and every image's manifest, config and layer digests. The builder also records its platform and its Docker Engine, BuildKit and Nix versions. The steps above then apply with those values in place of this release's.

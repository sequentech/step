Election Event File

The election event file contains the configuration of an election event. It can also contain its voters, logs, keys, publications and results. Use it to make a copy of an election event, or to move an election event to a different tenant or to a different installation.

Make the file with Export on the election event. Import it with Election Events > + > Import Election Event. Do not make this file yourself, and do not change it. This page describes the file so that you can examine it and find the cause of an import error.

File types​

File typeContent
.jsonThe configuration only: the JSON document that this page describes.
.zipA ZIP archive. It contains the JSON document and the other files that you selected in the export. See ZIP contents.
.ezipA .zip file that is encrypted with a password (AES-256-CBC).

The export always makes a .zip or an .ezip file. To get a .json file, extract the file export_election_event-<ID>.json from the archive.

File name​

The export gives the file this name:

election-event-<election event ID>-export-sha256-<hash>.zip

The extension is .ezip if the file is encrypted. The <hash> is the SHA-256 hash of the file. The name of a .json file is not important. In a .zip file, the import looks for an entry whose name contains export_election_event and ends with .json. If there is no such entry, the import stops with "No JSON file found in ZIP".

Password​

The export encrypts the file if you select Encrypt with Password, Bulletin Board, Reports or Applications. The admin portal then shows a password in the Password dialog. Keep the password. You cannot get it again.

To import an .ezip file, type the password in Decryption Password. The admin portal opens this dialog for each file whose name ends with .ezip. Do not change the extension.

Integrity hash​

CAUTION: hash of the election event file

In this version the admin portal does not send the hash of an election event file to the server, so the import does not check it. Compare the hash yourself before you import: the hash that shasum -a 256 <file> gives must be the same as the hash in the file name. A .zip or .ezip export can contain voter data and keys. Keep it in a protected location.

What the import changes​

The import does not copy the election event exactly. It makes these changes:

  • It adds the election event to the tenant that you are signed in to. It replaces the tenant_id of the file everywhere in the file.
  • It gives new IDs to the election event and to all its parts. It replaces each ID everywhere in the file, so the links between the parts stay correct. The IDs in the settings of the login flows (authenticator settings) do not change.
  • It resets the status of the election event: not published, voting_status and kiosk_voting_status NOT_STARTED, no voting period dates.
  • It resets the voting status and the voting period dates of each election, and sets initialization_report_generated to false.
  • It resets the statistics of the election event and of each election to 0 emails and 0 SMS sent.
  • It removes the public_key of the election event.
  • It makes a new bulletin board and a new electoral log for the election event and for each election. It replaces bulletin_board_reference with the new board.
  • It makes new protocol manager keys, unless the ZIP file contains protocol manager keys.
  • It makes the login realm of the election event again. See keycloak_event_realm.

The import keeps all other values, for example is_archived. An election event that was archived when you exported it is archived after the import.

If the file has no keys ceremony, the election event has no election key after the import. Do a new keys ceremony.

If the file has bulletin board data, the import keeps the keys ceremonies with their status and execution status. It removes the public_key of the election event. Ballot publication reads the election key from the status of the keys ceremony, and the import keeps that status, so a new keys ceremony is not needed for that key.

The import runs as a task. See its result in Tasks. If one part of the import fails, the import stops and the task shows the error. The election event is not added.

Version of the file​

This version (9.0) does not check the version of the file. The JSON document has no version field. An export from this version imports without a version check. A file from another version can fail to import if its structure differs. Use an export that this version made.

JSON structure​

The file is one JSON object. Most values are text, numbers, true or false, or JSON objects. All IDs are UUIDs. The import refuses an ID that is not a version 4 UUID.

A field that is "optional" can be absent or null. A field that is "required" must be present.

CAUTION: trustees in the election event file

Make sure that the tenant where you import has trustees with the same names as the trustees in trustee_ids. The import finds each trustee by its name. If a name is not found, the import fails with "Error parsing trustee_ids as UUIDs".

keycloak_event_realm​

The login realm of the election event. It contains the login configuration of the voters: the login pages and their texts, the languages, the voter fields (user profile), the login flows and their settings, the identity providers and the clients. The export always writes it.

The import makes the login realm of the new election event from this object:

  • It gives the realm the name tenant-<tenant ID>-event-<election event ID>.
  • It removes the client secrets. The system makes new secrets, or uses the secrets that the installation configures.
  • It removes the signing keys. It keeps only their algorithm and priority, so the system makes new keys.

If the object is absent, the import uses the default login realm of the installation. Do not change this object. To change the login configuration, use the admin portal after the import.

ZIP contents​

CAUTION: files in the election event ZIP archive

Do not edit the files in the ZIP archive. They come from an export, and the import expects them exactly as the export wrote them. A changed file can stop the import, or make an election event with wrong data.

The import finds each entry by a part of its name. <ID> is the ID of the exported election event. The export option is the check box in the Export Election Event dialog.

EntryOptionalContentExport option
export_election_event-<ID>.jsonNoThe JSON document. See JSON structure.Always
images/document_<document ID>_<name>YesThe images of the elections, contests and candidates. The import adds them as public documents with new IDs.Always, if there are images
export_voters-<ID>.csvYesThe voters. See Voters file.Include Voters
export_reports-<ID>.csvYesThe reports. See Reports file.Reports
export_activity_logs-<ID>YesThe electoral log in CSV format. The entry has no extension. The import adds the log messages to the electoral log of the new election event.Activity Logs
export_S3_files/document_<document ID>_<name>YesThe private documents of the election event. The import adds them with new IDs.S3 Files
export_scheduled_events-<ID>.csvYesThe scheduled events. See Scheduled events file.Scheduled Events
export_publications-<ID>.jsonYesThe ballot publications.Publications
export_protocol_manager_keys-<ID>.csvYesThe protocol manager keys. See Protocol manager keys file.Bulletin Board, Activity Logs or Publications
export_bulletin_boards-<ID>.csvYesThe messages of the bulletin boards. See Bulletin boards file.Bulletin Board, if there is a keys ceremony
export_tally_data/<name>.csvYesThe tally sessions and the results. See Tally data files.Tally (the admin portal also selects Bulletin Board)

The import reads the protocol manager keys first. Then it reads the other entries in alphabetical order. The tally files are read last.

Values in the CSV files that hold JSON (objects, arrays, quoted text) are written as JSON. For example, a text value is written with its quotes: "START_VOTING_PERIOD".

WARNING: election event export with reports

Keep an export with reports in a protected location. The reports file contains the passwords of the encrypted reports as plain text. For this reason the export always encrypts the archive when you select Reports.

Scheduled events file​

export_scheduled_events-<ID>.csv. One row for each scheduled event. The columns are the fields of scheduled_events, in this order:

id, tenant_id, election_event_id, created_at, stopped_at, archived_at, labels, annotations, event_processor, cron_config, event_payload, task_id

The import:

  • Gives each scheduled event a new ID, and does not use id, tenant_id and election_event_id.
  • Replaces the election_id in event_payload with the new ID of the election.
  • Makes a new task_id.
  • Clears stopped_at and archived_at. All imported scheduled events are active.

Protocol manager keys file​

export_protocol_manager_keys-<ID>.csv. The secret keys of the bulletin boards.

ColumnContent
election_idEmpty for the board of the election event. Otherwise the ID of the election of the board.
keyThe protocol manager key of the board.

The file must have one row for the election event and one row for each election. If a row is missing, the import fails. If this file is present, the import does not make new protocol manager keys.

WARNING: protocol manager keys file

Keep this file secret. The protocol manager keys protect the bulletin boards of the election event.

batchThe batch number.
mix_numberThe mix number.

Tally data files​

The folder export_tally_data/ contains ten CSV files. The import reads export_tally_session.csv and export_results_event.csv before the other tally files.

These columns are in most files:

ColumnContent
idThe ID of the row. The import gives a new ID.
tenant_id, election_event_idThe tenant and the election event. The import replaces them.
election_id, contest_id, area_id, candidate_idThe election, contest, area or candidate of the row. The import replaces them with the new IDs.
results_event_idThe results of the tally session.
created_at, last_updated_atWhen the row was made and last changed.
labels, annotationsFree key-value data as JSON.
documentsThe documents of the results (for example PDF, HTML, JSON) as JSON.
nameThe name of the results or of the area.

The files and their other columns:

FileContentOther columns
export_tally_session.csvThe tally sessions.election_ids, area_ids, is_execution_completed, keys_ceremony_id, execution_status, threshold, configuration, tally_type (ELECTORAL_RESULTS or INITIALIZATION_REPORT), permission_label
export_tally_session_contest.csvThe contests and areas of each tally session.session_id, tally_session_id
export_tally_session_execution.csvThe steps of each tally session.current_message_id, tally_session_id, session_ids, status
export_results_event.csvOne row for each set of results.—
export_results_election.csvThe results of each election.elegible_census, total_voters, total_voters_percent
export_results_election_area.csvThe results of each election in each area.—
export_results_contest.csvThe results of each contest.elegible_census, total_valid_votes, explicit_invalid_votes, implicit_invalid_votes, blank_votes, total_invalid_votes, total_votes, total_auditable_votes, the _percent column of each count, voting_type, counting_algorithm
export_results_area_contest.csvThe results of each contest in each area.The same counts and _percent columns as export_results_contest.csv
export_results_contest_candidate.csvThe results of each candidate.cast_votes, cast_votes_percent, winning_position, points
export_results_area_contest_candidate.csvThe results of each candidate in each area.cast_votes, cast_votes_percent, winning_position, points

The _percent columns are the same counts as a percentage. elegible_census is the number of voters who can vote.

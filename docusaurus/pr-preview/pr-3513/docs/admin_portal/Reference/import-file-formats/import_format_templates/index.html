Templates File

The templates file holds the templates of a tenant: the documents, emails and SMS messages that the platform makes for reports, credentials, ballot receipts and other uses. You make the file with Export on the Templates page. You import it with Import on the same page. Do not make the file by hand.

Use the import to copy the templates to another tenant, or to restore a backup. For the screen, see Templates.

CAUTION: tenant in the templates file

The import reads the tenant ID from each row. It does not use the tenant that you are signed in to. Import the file only into the tenant where you exported it.

Fields​

The file has a header row and ten columns. The order of the columns is fixed. The import reads the columns by position, not by name.

ColumnPositionRequiredAllowed values or formatDefaultMeaningExample
alias1RequiredTextNoneThe alias of the template. Reports and other functions find the template by its alias.ballot-receipt-1
tenant_id2RequiredA version 4 UUIDNoneThe tenant of the template. A row with a value that is not valid is skipped.90505c8a-23a9-4cdf-a26b-4e19f6a097d5
template3RequiredA JSON object, see belownullThe content of the template.See below.
created_by4RequiredTextNoneThe user that made the template.admin@example.com
labels5OptionalText (JSON)EmptyExtra data. You can leave it empty.{}
annotations6OptionalText (JSON)EmptyExtra data. You can leave it empty.{}
created_at7OptionalDate and timeNot usedThe import ignores the value. It sets the date of the import.2026-10-01 09:30:00 +00:00
updated_at8OptionalDate and timeNot usedThe import ignores the value. It sets the date of the import.2026-10-01 09:30:00 +00:00
communication_method9RequiredEMAIL, SMS or DOCUMENTNoneThe communication method of the template.EMAIL
type10RequiredOne of the types in the table belowNoneThe Template Type.BALLOT_RECEIPT

Values of type​

The value must be a template type of the admin portal. The import does not check the value. Use the value that the export writes for each template. Examples of values:

  • CREDENTIALS
  • INITIALIZATION_REPORT
  • ELECTORAL_RESULTS
  • BALLOT_IMAGES
  • BALLOT_RECEIPT
  • ACTIVITY_LOGS
  • MANUAL_VERIFICATION
  • PARTICIPATION_REPORT

The import does not check type or communication_method. A value that the admin portal does not know is imported, but the admin portal does not use the template.

Values of communication_method​

ValueMeaning
EMAILThe template makes an email.
SMSThe template makes an SMS message.
DOCUMENTThe template makes a document (PDF).

When you make a template in the admin portal, the admin portal writes EMAIL in this column, also if you select other methods. The methods that you select are in the JSON of the template (selected_methods).

The column template​

template is a JSON object. These are the keys that the admin portal writes:

KeyTypeMeaning
aliasTextThe alias of the template. It is the same as the column alias.
nameTextThe name of the template.
selected_methodsObjectThree keys, EMAIL, SMS and DOCUMENT. Each value is true or false. It shows which parts the template has.
emailObjectThe email part. It has subject, plaintext_body and html_body.
smsObjectThe SMS part. It has the key message.
documentTextThe document part: the text of the document, as an HTML template.
pdf_optionsObjectThe PDF settings of the document, for example landscape, print_background, scale, paper_width, paper_height, margin_top, margin_bottom, margin_left, margin_right, page_ranges, header_template, footer_template.
report_optionsObjectThe report limits. It has max_items_per_report and max_threads.

The texts of the email, the SMS and the document can contain variables. The platform replaces them when it makes the message or the document.

For a message to a voter, the platform fills these variables: user.first_name, user.last_name, user.username, user.email, user.attributes, tenant_id, and each attribute of the voter as user.<attribute name>. If the message belongs to an election event, it also gets election_event.id, election_event.name and vote_url.

Example of the value of template:

{
  "alias": "ballot-receipt-1",
  "name": "Ballot receipt 1",
  "selected_methods": {"EMAIL": true, "SMS": false, "DOCUMENT": true},
  "email": {"subject": "Your ballot receipt", "plaintext_body": "Your receipt is attached.", "html_body": "<p>Your receipt is attached.</p>"},
  "sms": {"message": ""},
  "document": "<html><body><h1>Receipt</h1></body></html>",
  "pdf_options": {"landscape": false, "print_background": true},
  "report_options": {"max_items_per_report": 1000, "max_threads": 4}
}

Rules​

RuleValue
File type.csv. The separator is a comma.
HeaderThe export writes a header row. The import does not skip it. It skips it because the value tenant_id is not a valid UUID. A file without a header row works.
EncodingUTF-8.
QuotesThe JSON columns are in double quotes. Each quote inside is doubled. Do not change this.
Order of columnsFixed.
PermissionThe user needs the Edit Communication Template permission.
Duplicate aliasesThe import does not check them. If a template with the same alias exists, the import adds a second one.
SizeThe size is limited by the deployment setting for file uploads.
Empty exportIf the tenant has no templates, the export fails with the error No templates available to write.
CAUTION: template aliases

Use a different alias for each template. If two templates have the same alias, the admin portal can use either of them.

Example file​

alias,tenant_id,template,created_by,labels,annotations,created_at,updated_at,communication_method,type
ballot-receipt-1,90505c8a-23a9-4cdf-a26b-4e19f6a097d5,"{""alias"":""ballot-receipt-1"",""name"":""Ballot receipt 1"",""selected_methods"":{""EMAIL"":false,""SMS"":false,""DOCUMENT"":true},""document"":""<html><body><h1>Receipt</h1></body></html>""}",admin@example.com,{},{},2026-10-01 09:30:00 +00:00,2026-10-01 09:30:00 +00:00,DOCUMENT,BALLOT_RECEIPT

What the import does​

  1. The admin portal uploads the file and asks for the Integrity Check (SHA-256). The server checks the hash if you typed one.
  2. The import runs on the server while the portal waits for the result. No task starts. The Tasks tab does not show the import. The import does not try again if it fails.
  3. For each row, the server reads the ten columns. It skips a row if tenant_id is not a valid version 4 UUID.
  4. The server adds all the other rows in one database transaction. If the database refuses one row, the server adds nothing.
  5. Each row becomes a new template. The import never changes or removes a template that exists.
  6. The dates created_at and updated_at are the date of the import.

If the JSON in template is not valid, the import saves null and does not show an error. The template then does not work. Open the template in the admin portal to check it.

Known effect: the import stores labels and annotations as a JSON text and not as a JSON object.

Messages and errors​

MessageWhereMeaning and action
Templates imported successfullyNotificationThe import finished. Check the Templates page.
Hashes don't match. Integrity check failure.NotificationThe typed hash is not the hash of the file. Check the hash and the file.
Error importing templatesNotificationThe import failed. No template was saved. The portal does not show the reason. Check the file, then import it again.

Voter File

The voter file is a text file with one row for each voter. You make it yourself, for example from a voter list or a spreadsheet. You import it in an election event, on the Voters tab, with Import. For the steps, see Add the Voters.

The same file format is used on the Users page of the tenant, to import administrators. In that case, the import does not look up areas and does not read secret attributes.

Fields​

The first row of the file is the header. The header names the columns. The order of the columns is not important. All columns are optional. The table lists the columns that have a special meaning.

Area​

  • The import looks for the area by its name, in the election event. The name must be exactly the same as on the Areas tab.
  • If the import does not find the area, it does not stop. The voter has no area. A voter without an area cannot be linked to the elections of an area. Check the area of each voter after the import.
  • area_name and area-id are the same field. If the file has both, the import stops with the error Duplicate column.

Group​

The import adds each voter to the group in group_name. If the file has no group_name column, the group is voter. If the realm has no group with this name, the import does not add the voter to a group and does not show an error.

Password​

Use one of these options. If you do not use any, the voter has no password. This is the normal case when the voters sign in with other data, or when you send the access data later.

  • Plain password. Use the column password. The import makes a random salt for each voter and hashes the password with PBKDF2-SHA256 and 27 500 iterations. The import stores only the hash.
  • Hashed password. Use the columns hashed_password and password_salt. Both values are Base64 text. The algorithm is PBKDF2-SHA256 and the hash length is 32 bytes. Add num_of_iterations if the hash uses another number of iterations. If the cell is empty, is not a number or is 0, the import uses 27 500.

If the file has the columns password and hashed_password, the import uses password. If hashed_password has no password_salt, the import stops with the error Password salt empty.

CAUTION: voters file with passwords

Do not keep a file with plain passwords. Delete the file after the import. If you can, give the voters their access data with the Send option of the admin portal, and do not use the password column.

Vote weight​

Use vote-weight only if the election event has the weighted voting policy Weighted Voting for Voters. If the policy is another one, the column is stored but the tally does not use it.

  • The value is a whole number from 1 to 100 000. The import also accepts +5 and 007, and stores them as 5 and 7.
  • An empty cell means weight 1.
  • The name of the column is exactly vote-weight, in lower case, with a hyphen. Names like vote_weight or VoteWeight make the import stop with an error.
  • The sum of the weights of the voters of one contest area is limited to 1 000 000. The import does not stop if the file is over this limit. It writes a warning in the server log. Later, the tally refuses to count the voters of that area.

Authorized elections​

The column authorized-election-ids limits the elections where the voter can vote. Each value is the External ID of an election. If an election has no External ID, use the ID of the election. Separate the values with |.

  • If the cell is empty and the voter has an area, the voter can vote in the elections of the area. If the area has no elections, the voter is authorized for all elections of the election event.
  • If the cell is empty and the voter has no area, the voter is authorized for all elections of the election event.
  • A value that does not match any election is ignored.

Write the External ID of the election. The voter token uses the External ID, or the ID if the election has none. The tally matches only the External ID, so for an election without one the tally does not match the voters' values.

Secret attributes​

An attribute can be marked as secret in the user profile of the election event. The import then stores the value encrypted.

  • The user must have the permission Edit Secret Voter Fields (voter-secret-attribute-write). If a secret column is in the file and the user does not have the permission, the import stops with the error Importing encrypted voter attributes requires voter-secret-attribute-write.
  • One value can have at most 150 bytes. A longer value stops the import. Use | to give more than one value. Each value has the limit.
  • An empty cell is not encrypted.
  • These attributes cannot be secret: area-id, authorized-election-ids, authorized-to-election-alias, dateOfBirth, disable-comment, email, firstName, first_name, lastName, last_name, permission_labels, sequent.read-only.id-card-number-validated, sequent.read-only.mobile-number, tenant-id, username, vote-weight and voted-channel. If the user profile marks one of them as secret, the import stops.
  • A secret attribute cannot use Keycloak value validators. Only the validator person-name-prohibited-characters is allowed.
  • The import writes an entry in the electoral log with the names of the secret columns and the user who did the import.

Rules​

RuleValue

SizeThe import code does not check the file size.
Order of rowsNot important.
NOTE: optional columns of the voters file

The columns password, hashed_password, password_salt, num_of_iterations, group_name, email_verified and sequent_internal_user_id are never stored as attributes. All other columns that are not username, email, first_name, last_name, enabled and election__... become attributes.

Example file​

username,email,first_name,last_name,area_name,enabled,group_name,password,vote-weight,authorized-election-ids,sequent.read-only.mobile-number,dateOfBirth
voter001,voter001@example.com,Ana,Lopez,North,TRUE,voter,Example-Pass-1,1,,+10000000001,1990-01-31
voter002,voter002@example.com,Ben,Smith,South,TRUE,voter,Example-Pass-2,3,election-1|election-2,+10000000002,1985-06-15
voter003,voter003@example.com,Eva,Brown,North,FALSE,voter,,,,,

The first voter votes with weight 1 in all elections of the area North. The second voter votes with weight 3 in election-1 and election-2. The third voter is disabled and has no password.

What the import does​

  1. The admin portal uploads the file. Then it asks you for the Integrity Check (SHA-256). If you click Import with an empty field, the portal asks Import Without Integrity Check?. Click Yes, Import without Integrity Check or Go Back.
  2. The portal starts the task Import Users and shows it in the task widget. The message Voters Import Scheduled Successfully is not a result of the import. It only confirms that the task started.
  3. The task checks the hash. It checks the header. It checks the permission for secret columns.
  4. The task creates all voters in one database transaction. If one row is wrong, the task makes no change. The task status is Failed and the log of the task has the reason. Correct the file and import it again.
  5. After a good import, the voters show on the Voters tab. The import does not send emails or messages.

If the file has at least one column that becomes an attribute (for example area_name), the import also gives each voter the attribute tenant-id.

A file without such a column gives the voters no tenant-id attribute.

Ballot Audit Manual

This manual tells election auditors how to check that the ballots in a tally are the ballots that the voters cast. You do the audit offline, on restored copies of the election data. You do not need the election application or access to the production systems.

This manual explains how to run the audit. For what each check establishes, read What the Ballot Audit Verifies. That explanation follows the checks from signed cast records through encrypted inputs, verified mixes and published plaintext records.

What the audit checks​

The audit connects four records of each selected ballot:

  1. The signed record in the electoral log that the voter cast the ballot.
  2. The stored ballot and its receipt.
  3. The supplied eligibility list and the rule that selects each voter's latest cast row marked valid.
  4. The encrypted ballots that went into the tally on the bulletin board.

A separate check with Braid verifies the public key, the mix evidence and the decryption proofs, and recomputes the plaintexts of every batch. You must do both parts of this audit. The audit-tally command runs both parts for the areas and contests in the supplied tally mappings.

How to use this manual​

  1. Read Before You Start first. It gives the roles, the terms and the safety rules.
  2. Do the procedures in the order of the table. Each procedure tells you what you must have before you start.
  3. Use Read the Results to understand each result.
  4. Use Troubleshooting when a command stops with a message.
  5. Use Command Reference for all options of the commands and the format of the input files.
  6. Use File Reference for the content of the files that the commands write.
  7. Use Appendix: Run Each Step Separately to run one command at a time.

Procedures​

If the election authority supplied a package with the one-argument run-audit.sh, follow Run a Prepared Client Package. It replaces steps 1–3 below. The launcher supplies the packaged public values; their independent authentication is still required.

Use the following steps when you have a raw image and separate backups.

StepProcedureContentResult
Before You StartRoles, terms, versions and safety rulesYou know who does each task.
1Set Up the Audit WorkstationDocker and the audit imageThe audit image is on the workstation.
2Prepare the BackupsThe backups of the four databases and their digestsOne directory with the backups.
3Run the AuditOne docker run command for all areas and contests of the tallyAn audit record and a public summary.
4Report and Remove the CopiesThe audit report and the clean-upA published summary. No copies are left.

To repeat or examine one step of the audit, or to work without the audit image, use Appendix: Run Each Step Separately.

Scope of this manual​

This manual describes the proposed ballot audit tools for the 10.0 release line. See Versions. Each audit run covers one tally, with all its areas and contests represented in the supplied mappings. The manual does not cover the final count or the electoral log database's history proofs. It does not establish a link between a voter and a decrypted vote.

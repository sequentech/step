# Blank-rule characterization — layer 3 (booth filter + dialog wiring)

Generated by `characterization/blank-rule.browser.mjs`; do not edit by hand.

**Experiment:** every row is the same act — the voter leaves the ballot
**empty** — under a different `blank_vote_policy`
(`invalid_vote_policy` at its default, `allowed`). Columns are the
moments at which the screen is observed:

- *untouched* — the voting screen before any interaction with the contest;
- *touched, voting* — the voting screen after selecting and deselecting a
  candidate (ballot empty again, contest now touched — the filter's touch
  gate suppresses everything for untouched contests, so this is the
  earliest a warning can appear);
- *transition dialog* — what clicking Next/Review produces;
- *review* — the review screen, when reachable.

Cell values are the message keys of the warning boxes visible at that
moment, read from each box's `data-warn-id` attribute (locale-
independent); keys are shown without their `errors.implicit.` prefix.
`—` = no warning box visible.

| blank policy | untouched | touched, voting | transition dialog | review |
|---|---|---|---|---|
| allowed | — | — | none | — |
| warn | — | `blankVote` | dismissible (Cancel/Continue) | `blankVote` |
| warn-only-in-review | — | — | none | `blankVote` |
| not-allowed | — | `blankVote` | **blocking** (Review selection) | unreachable |

# B4 Testing Scripts - Summary

## Overview
Testing scripts for the B4 / braid stack with support for the **ciphertext width (W)** parameter.

## Scripts

### 1. **demo-multi.ps1** ✅
- **Purpose**: Native-only multi-board protocol demo
- **Parameters**:
  - `-CiphertextWidth <int>` (default: 2) - Sets the W parameter for ciphertext width
- **Usage Examples**:
  ```powershell
  # Quick test with default W=2
  .\demo-multi.ps1 -QuickTest
  
  # Test with W=1 (single element ciphertexts)
  .\demo-multi.ps1 -NumTrustees 3 -Threshold 2 -NumBallots 10 -CiphertextWidth 1
  
  # Test with W=3
  .\demo-multi.ps1 -NumTrustees 5 -Threshold 3 -NumBallots 100 -CiphertextWidth 3
  
  # Test with W=4
  .\demo-multi.ps1 -CiphertextWidth 4 -QuickTest
  ```

### 2. **demo-browser.ps1** ✅
- **Purpose**: Browser + Native trustees demo
- **Parameters**:
  - `-CiphertextWidth <int>` (default: 2) - Sets the W parameter
- **Prerequisites**:
  - LocalStack running (`.\localstack.ps1`)
  - WASM build complete (`.\build-wasm.ps1`)
  - Web server running in a separate terminal (`.\serve.ps1`) so the browser trustee page is reachable
- **Usage Examples**:
  ```powershell
  # Default W=2
  .\demo-browser.ps1
  
  # Test with W=1
  .\demo-browser.ps1 -NumTrustees 3 -Threshold 2 -NumBallots 10 -CiphertextWidth 1
  
  # Custom browser trustee slot with W=3
  .\demo-browser.ps1 -BrowserTrusteeIndex 2 -CiphertextWidth 3
  ```

## Invocation Details

### Package Targeting
- `--package braid --bin demo_tool`
- `--package b4 --bin b4`
- `--package braid --bin main_concurrent`

### Ciphertext Width Parameter
All scripts accept the `-CiphertextWidth <int>` parameter:
- Passed to `demo_tool gen-configs --ciphertext-width $CiphertextWidth`
- Default value: 2
- Supported values: 1, 2, 3, 4 (per dispatch macro)

### Stack
- **Messages**: b4
- **Protocol**: braid
- **Crypto**: cryptography (vsc crate)
- **Server**: b4 binary

## Testing Workflow

### Native-Only Testing (Simplest)
```powershell
# 1. Clean build
cargo build --package braid --package b4 --release

# 2. Test with W=2 (default, backward compatible)
.\demo-multi.ps1 -QuickTest

# 3. Test with W=1
.\demo-multi.ps1 -QuickTest -CiphertextWidth 1

# 4. Test with W=3
.\demo-multi.ps1 -QuickTest -CiphertextWidth 3

# 5. Test with W=4
.\demo-multi.ps1 -QuickTest -CiphertextWidth 4
```

### Browser Testing (Full Stack)
```powershell
# 1. Start LocalStack (required for S3)
.\localstack.ps1

# 2. Start the web server in a separate terminal (also builds WASM)
.\serve.ps1

# 3. Run browser demo (in another terminal)
.\demo-browser.ps1 -CiphertextWidth 2

# 4. Follow on-screen instructions to connect browser trustee
```

## What Each Script Does

### demo-multi.ps1 Flow:
1. **Cleanup**: Remove old databases and processes
2. **Generate Config**: Create trustee configs with W parameter
3. **Start B4 Server**: Launch bulletin board on port 3000
4. **Initialize Boards**: Create N boards with shared config
5. **Start Trustees**: Launch M native trustees (minimized windows)
6. **Wait for DKG**: Pause for key generation
7. **Post Ballots**: Add encrypted ballots to boards
8. **Monitor Progress**: Check for completion
9. **Verify**: Confirm all messages present

### demo-browser.ps1 Flow:
1. **Prerequisites Check**: Verify LocalStack & WASM build
2. **Cleanup**: Remove old state
3. **Generate Config**: Create trustee configs with W parameter
4. **Start B4 Server**: Launch bulletin board
5. **Initialize Board**: Single board for browser test
6. **Extract Browser Config**: Get keys for browser trustee
7. **Start Native Trustees**: All except one slot
8. **Display Instructions**: Show browser setup steps (including running `serve.ps1`)
9. **Wait for User**: Pause until browser connects
10. **Post Ballots**: After browser trustee ready
11. **Monitor**: Wait indefinitely (Ctrl+C to exit)

## Binaries Used

### From braid:
- `demo_tool`: Generate configs, init protocol, post ballots, list messages
- `gen_trustee_config`: Generate individual trustee configs
- `main_concurrent`: Run trustee instance (single or multi-board)

### From b4:
- `b4`: Bulletin board server (HTTP API + SQLite + S3)

## Troubleshooting

### "Failed to generate configuration"
- Check that braid builds successfully
- Verify demo_tool binary exists

### "b4 server failed to start"
- Check port 3000 isn't in use
- Verify LocalStack is running (for S3 features)
- Look at b4 server window for errors

### "Browser trustee can't connect"
- Ensure build-wasm.ps1 ran successfully
- Check crates/braid/pkg/ directory exists
- Verify web server running on port 8080

### "Trustees stuck at DKG"
- For browser demo: ensure browser trustee connected
- Check trustee windows for errors
- Verify threshold ≤ number of active trustees

## Notes

- **Database**: Scripts use the `b4.db` filename
- **Serve Script**: Browser testing uses `serve.ps1`, which builds the WASM client and starts the Python web server on port 8080
- **Quick Test**: `-QuickTest` flag reduces trustees/ballots for fast validation

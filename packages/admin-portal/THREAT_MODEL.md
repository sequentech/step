# admin-portal threat model

admin-portal is the React Admin single-page application that election managers, restricted administrators and trustees run in their own browsers. They use it to configure tenants and election events, manage voters, run the key and tally ceremonies, publish ballots and results, and open or close voting. It has no server code. Every read and write goes to Hasura GraphQL with the user's Keycloak token. Hasura serves it through table permissions or through actions handled by harvest, which hands long jobs to windmill. The portal's own permission checks only decide what the UI shows, so the security of an election rests on Hasura, harvest and Keycloak. The package itself decides how the browser handles session tokens, trustee key shares, passwords and voter data, how it shows tenant-supplied content, and which code and configuration the browser loads. See the [system threat model](../../THREAT_MODEL.md).

## Assets

- **Admin and trustee sessions**: Keycloak access and refresh tokens from the tenant realm `tenant-<id>` (client `admin-portal`). keycloak-js manages them and the portal sends the access token as `Authorization: Bearer` on every GraphQL call. Confidentiality: a stolen token carries all the user's roles.
- **Trustee key shares**: each trustee's encrypted DKG share, downloaded in `src/components/keys-ceremony/DownloadStep.tsx` and uploaded again for the check and the tally restore. Confidentiality, and availability because tallying needs a threshold of shares.
- **Trustee configuration export**: one archive with every trustee's configuration, requested from `src/resources/Settings/SettingsTrustees.tsx` `doExport` and protected by a password. Confidentiality.
- **Voter certificate trust anchors**: the certificate authorities of an election event, managed in `src/resources/ElectionEvent/EditElectionEventCAs.tsx`, which keycloak-extensions loads for voter certificate login. Integrity.
- **Election configuration and state**: the election event public key, trustee public keys, election and event status, ballot styles, ballot publications, scheduled events and voting channels. Integrity, because these decide what voters encrypt to and when they can vote.
- **Ceremony and tally state**: keys ceremonies, tally sessions and results. The results database is downloaded and queried in the browser by `src/hooks/useSQLiteDatabase.ts`. Integrity, and confidentiality until publication.
- **Voter data**: PII in user lists, approvals, IP and country statistics and the electoral log; voter secret attributes, which harvest redacts and reveals only on request; voter passwords set by admins and voter-information-letter passwords. Confidentiality.
- **Passwords, keys and credentials**:
  - election-event export passwords, generated by harvest;
  - the trustee-configuration export password;
  - import and report passwords;
  - the Miru SBEI PKCS#12 key file and passphrase (`src/components/MiruExportWizard.tsx`);
  - third-party integration credentials entered in `src/resources/Settings/SettingsIntegrations.tsx`.

  Confidentiality.
- **Sensitive documents**: event exports, trustee configuration archives, tally archives and voter CSVs in object storage. The portal reaches them through presigned URLs from `fetch_document` and `get_upload_url`. Confidentiality.
- **Tenant configuration**: tenant `settings` and `annotations` (branding, custom CSS, help links, translations), and the Keycloak realm configuration carried in imports and exports. Integrity.
- **External configuration and transmissions steered from the portal**: DNS records and redirect rules for custom voter URLs, and the results transmission package. Integrity, because voters and receiving authorities rely on them.
- **Audit logs**: the electoral log shown read-only in the portal. Confidentiality of its content. The backends own its integrity.
- **The portal's code**: the bundle; `/global-settings.json`; TinyMCE (copied from npm by `postinstall.cjs`), the committed `public/sql-wasm.*` and `public/intl-tel-input/phoneInput.js`; the committed sequent-core WASM package; and the IVR emulator loaded at runtime. Integrity, because any code running in the portal origin acts with the admin's session.

## Threats

| ID | STRIDE | Threat | Controls in the code | Status |
|---|---|---|---|---|
| admin-portal-T1 | Spoofing | Someone without a session uses administration data or actions. | Login required per tenant realm (`src/providers/AuthContextProvider.tsx` `initializeKeycloak`). Bearer token on every call (`src/providers/ApolloContextProvider.tsx` `createApolloClient`). Hasura gives requests without a token the `unauthorized` role, which is limited to public tenant fields. | Mitigated |
| admin-portal-T2 | Information disclosure | The GraphQL endpoint is used without a session to gather information or to exhaust resources. | Anonymous access is limited to public tenant fields. Rate, depth and size limits are left to the deployment. | Partial |
| admin-portal-T3 | Elevation of privilege | A user of one tenant reads or changes another tenant's data. | Tenant-scoped Hasura permissions on admin roles, with the tenant claim from Keycloak. harvest `authorize` (`../sequent-core/src/services/authorization.rs`) checks the caller's tenant. | Partial |
| admin-portal-T4 | Elevation of privilege | A user acts outside their assigned permissions or election labels. | Hasura per-role rules. harvest per-handler permission lists. The portal's `getOperationRole` and `isAuthorized` are client-side only. | Partial |
| admin-portal-T5 | Tampering | Critical election state changes are made without fresh step-up authentication. | Client `isGoldUser` and `reauthWithGold` in `src/providers/AuthContextProvider.tsx`. harvest checks a gold step-up claim. | Partial |
| admin-portal-T6 | Spoofing | An admin or trustee session token is stolen from the browser (XSS, browser extensions, other code running in the portal origin). | No raw-HTML sinks in `src/` (no `dangerouslySetInnerHTML`, `innerHTML` or `eval`). Short-lived access tokens (Keycloak realm setting). `logout` in `src/providers/AuthContextProvider.tsx`. | Partial |
| admin-portal-T7 | Spoofing | The `admin-portal` OIDC client is misused to obtain an admin's tokens. | keycloak-js standard flow (`initializeKeycloak`, `initKeycloak`). The client's settings are Keycloak configuration (deployment). | Not verified |
| admin-portal-T8 | Information disclosure | A trustee key share is obtained by someone other than its trustee, or outside the ceremony window. | `src/queries/GetPrivateKey.ts`, `CheckPrivateKey.ts` and `RestorePrivateKey.ts` send no trustee name. `validate_private_key_download` (`../windmill/src/services/ceremonies/keys_ceremony.rs`) requires `IN_PROGRESS`, a trustee of the ceremony and a share not yet checked. UI gate `isDownloadUnavailable`. | Partial |
| admin-portal-T9 | Information disclosure | The downloaded encrypted share stays reachable in the page after download. | `src/components/keys-ceremony/DownloadStep.tsx` `download` does not revoke the blob URL. | Open on release/10.0 (fix in sequentech/step#3522) |
| admin-portal-T10 | Denial of service | One malformed electoral-log entry stops the log viewer from rendering. | `src/components/ElectoralLogList.tsx` parses each `message` with `JSON.parse` and does not handle non-JSON input. | Open on release/10.0 (fix in sequentech/step#3522) |
| admin-portal-T11 | Tampering | A tenant writer uses tenant presentation content to mislead or attack other admins. | `src/components/CustomMenu.tsx` `openInNewTab` opens help links with `noopener,noreferrer`. Content-Security-Policy is set by the deployment. | Partial |
| admin-portal-T12 | Information disclosure | Document passwords, voter secret attributes or PII reach roles, logs, consoles or files that do not need them. | `redact_user` (`../windmill/src/services/voter_secret_attributes.rs`) on user listings, and audited reveals. `fetchPolicy: "no-cache"` in `src/resources/Reports/ReportPasswordDialog.tsx`, `src/resources/User/EditUserForm.tsx` and `src/resources/User/ListUsers.tsx`. Permissions `document-password-read` and `voter-secret-attribute-read`. | Partial |
| admin-portal-T13 | Information disclosure | Sensitive data stays in the browser after the session ends. | `logout` in `src/providers/AuthContextProvider.tsx` ends the Keycloak session. | Partial |
| admin-portal-T14 | Tampering | Import packages and uploads (event, tenant configuration, voters, tally sheets, public files) carry harmful content or exhaust server resources. | Sensitive uploads are private (`is_public: false`). Integrity hashes for tally sheets, and optionally for event imports. Object keys are prefixed with the claim tenant and a server-generated document id. Parsing and validation happen on the server. | Not verified |
| admin-portal-T15 | Elevation of privilege | Admin-written templates abuse the server-side renderers (PDF, email, SMS). | Rendering happens in windmill and sequent-core. | Not verified |
| admin-portal-T16 | Tampering | User-controlled values are injected into GraphQL documents or local SQL. | Documents in `src/queries/*` are static and pass values as variables. `src/queries/customBuildQuery.ts` `customBuildQuery` drops list filter and sort fields not in `COLUMNS_MAP` (`src/types/query.ts`) for the resources listed there. `useSQLQuery` in `src/hooks/useSQLiteDatabase.ts` calls `db.prepare(sql, params)`. | Partial |
| admin-portal-T17 | Tampering | Code from outside the reviewed source runs in the portal origin (runtime-loaded modules, prebuilt WASM, vendored scripts). | TinyMCE, sql.js and intl-tel-input are served from the portal origin. | admin-portal-T18 | Repudiation | An administrative change cannot be traced to the admin who made it. | harvest and windmill write electoral-log entries for ceremony, publication and voting-status actions. | admin-portal-T20 | Spoofing | An admin changes the certificate authorities an election event trusts, so certificates that should not log voters in are accepted. | harvest requires `CA_WRITE` to import or delete; windmill parses the certificates. | Partial |
| admin-portal-T21 | Information disclosure | Build-time secrets or internal details end up in the public bundle. | Left to the build environment (deployment). | Not verified |
| admin-portal-T22 | Information disclosure | Third-party integration credentials configured in the portal are disclosed. | Entered behind the `TENANT_WRITE` UI gate. Storage and access are server-side (outside this package). | Not verified |
| admin-portal-T23 | Elevation of privilege | The SBEI PKCS#12 passphrase typed in `src/components/MiruExportWizard.tsx` is built into `sh -c` command lines and logged by harvest and windmill. | The portal sends it only as a GraphQL variable and clears `passwordState` after `handleUploadSignature`. | admin-portal-T24 | Tampering | The results transmission started from `MiruExportWizard.tsx` `handleSendTransmissionPackage` is intercepted, because the CCS upload in `../windmill/src/services/consolidation/send_transmission_package_service.rs` does not check TLS certificates. | harvest requires `MIRU_SEND`; windmill refuses to send while fewer signatures than the configured threshold exist. | admin-portal-T25 | Tampering | Changes the portal triggers in external systems (DNS, redirects, transmissions) are misused. | harvest permission checks; windmill applies the changes (outside this package). | Not verified |
| admin-portal-T26 | Tampering | Lists exported to CSV in the browser carry spreadsheet formulas from untrusted values. | Exports use react-admin `ExportButton` (`src/components/ListActions.tsx`). | Not verified |
| admin-portal-T27 | Elevation of privilege | An admin gives themselves or others more privileges than they hold. | harvest permission checks on user and role management. | Partial |
| admin-portal-T28 | Spoofing | Voter communications sent from `src/resources/User/SendTemplate.tsx` are abused to phish voters or to mail voter secret attributes. | harvest requires `NOTIFICATION_SEND`, plus `VOTER_SECRET_ATTRIBUTE_READ` and `post_voter_secret_attribute_audit` for secret attributes. windmill logs sends (`post_send_template`). ## Assumptions

- **Hasura** checks the token signature and expiry, builds session variables only from token claims, and gives requests without a token the `unauthorized` role.
- **harvest** is reachable only through Hasura actions and checks the caller's tenant and permissions on every request.
- **Keycloak** realm, client and gold `acr` step-up configuration follows current security practice.
- **The deployment** serves the bundle, `/global-settings.json` and any runtime-loaded code over TLS from trusted origins, sets Content-Security-Policy, frame-ancestors and HSTS at the ingress, enforces GraphQL rate and size limits, and restricts access to service logs.
- **Object storage** keeps the public bucket writable only by the backend and on an origin separate from the portals, and presigned URLs are short-lived.
- **windmill and harvest** validate what they import and render, and protect the passwords and key material they handle.
- **Trustees** keep their encrypted share files offline and separate. **Admins** use trusted, personal workstations.
- The prebuilt and vendored code shipped with the portal comes from reviewed sources, and production builds run in a trusted environment.
- **keycloak-extensions** validates voter certificates against the certificate authorities configured for the election event.

## Review focus

1. Hasura permission rules for the administrator and trustee roles. Every control in this portal depends on them.
2. Authorization, step-up and audit logging of election state changes.
3. Tenant and permission checks in the harvest handlers the portal calls.
4. Server-side storage and handling of secrets, passwords, key material and exports.
5. Server-side rendering of admin-written templates, and changes the portal triggers in external systems.
6. Election-event and tenant-configuration import.
7. Tenant-configured content shown in admin sessions, and the portal's response headers.
8. Keycloak realm and client configuration.
9. Trustee configuration export and certificate-authority management.
10. Upload handling and CSV export.
11. What the browser keeps after logout.
12. Code loaded at runtime or shipped prebuilt, and how the bundle is built.
